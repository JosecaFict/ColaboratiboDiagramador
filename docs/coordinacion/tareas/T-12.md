## Por qué existe
El docente pide que el backend generado se **vea funcionando con un frontend**, sea cual sea el
proyecto. El zip ya trae una "Consola de prueba" en `GET /` (`GeneradorSpringBoot.consola()`,
`resources/static/index.html`), que se arma leyendo `app-manifest.json` y sirve a las dos
variantes. Hoy solo lista, crea y borra.

## Hallazgo del colíder (D-10): hoy la consola probablemente no funciona
`consola()` lee `endpoint`, acciones `crear`/`eliminar` y tipo `int`, pero `ManifestDeApp` emite
`path`, `create`/`update`/`delete` e `integer`. **Primero se corrige el consumidor** contra el
manifiesto real generado (respetando `actions` y entidades abstractas). `manifestVersion` sigue
en 1 y las plantillas de la API no cambian.

## Objetivo
Que la consola cubra el CRUD completo, siempre genérica (solo desde el manifiesto, sin conocer
entidades) y en un solo archivo, sin build ni dependencias externas:
1. **Editar** un registro (PUT o PATCH, con `version` para el bloqueo optimista: un 409 por versión
   vieja se muestra claro y ofrece recargar).
2. **Relaciones con lista:** un campo `reference` se elige de un `<select>` con los registros de
   la entidad destino (con una etiqueta legible, no el UUID), no escribiendo el id.
3. **Paginación y orden** con `page`, `size`, `sort` y `X-Total-Count`.
4. **Errores del backend visibles:** el formato `{"error", "errores": {campo: msg}}` se muestra junto
   a cada campo (400) o como aviso (404, 409, 500).
5. Tipos: fechas con `<input type="date">` / `datetime-local`, booleanos con casilla, enumerados
   con lista; campos obligatorios marcados.

## Precisiones del colíder (dictamen sobre D-10 en `DECISIONES.md`, puntos 1 a 5)
- **Versión:** no asumir `version`. `Meta.para` usa `versionRegistro` cuando el dominio ya ocupa
  `version`, `createdAt` o `updatedAt`. Está autorizado el cableado mínimo `consola(meta)` (y extraer
  `PlantillaConsola`) para pasarle el nombre técnico, sin tocar el manifiesto. Enviar la versión
  leída; ante 400 o 409 conservar el borrador y ofrecer recargar, sin reintentar solo. Preferir
  PATCH; si se usa PUT, mandar el registro completo.
- **Referencias:** resolver `target` contra las entidades del manifiesto; etiqueta legible con un
  respaldo que distinga registros y se envía el id. Al editar se conserva la referencia actual y
  las opcionales se pueden vaciar.
- **Tipos:** distinguir `null`, `false`, cero y campo omitido (un booleano opcional necesita tres
  estados). No convertir `embedded` ni `list` en texto ni borrarlos al guardar. Si un tipo
  obligatorio no se puede editar con el manifiesto actual, se declara el límite antes de decir
  "CRUD completo".
- **Seguridad:** etiquetas, datos y errores se muestran como texto, nunca como HTML.
- **Paginación:** páginas desde 0 con el total de `X-Total-Count`; volver a la página 0 al cambiar
  entidad, tamaño u orden; ajustar la última página tras borrar; ordenar solo por campos que la
  API admita; una respuesta tardía de otra entidad no reemplaza la vista actual.
- **409:** distinguir el de versión del de integridad o del recorte de MongoDB (D-02) por el
  mensaje del backend.
